ScreenBlink integration findings

At the requested ScreenBlink commit, the repository tree has no LICENSE, COPYING or NOTICE file, and its private package manifest names no license. Its README and package author field identify Katun Li. That grants no permission to adapt its code, copy, modify or redistribute it under BlinkMore’s MIT license. Keep BlinkMore’s existing MIT notice and original attribution intact, and get a separate grant before reusing ScreenBlink source. The icons and two MP3 files also have no provenance record in this tree, so treat them as uncleared. The evidence is in the [pinned ScreenBlink tree](https://github.com/katunli/ScreenBlink/tree/8b801ce1d43a285938f5fb07ca8bed7a20231080), [README](https://github.com/katunli/ScreenBlink/blob/8b801ce1d43a285938f5fb07ca8bed7a20231080/README.md) and [package manifest](https://github.com/katunli/ScreenBlink/blob/8b801ce1d43a285938f5fb07ca8bed7a20231080/package.json). BlinkMore’s fork retains the [MIT license](https://github.com/Solips1sm/BlinkMore/blob/91f832b4ad0aaf8e7e802c561a4881356a6b6674/LICENSE.md).

ScreenBlink bundles dlib’s 68 point landmark model. The official [dlib landmark example](https://github.com/davisking/dlib/blob/master/examples/face_landmark_detection_ex.cpp) says the model was trained on iBUG 300-W and that dataset terms exclude commercial use. The dlib library’s Boost license does not clear the separate model and dataset rights. Do not carry the model or this Python tracking path into BlinkMore without clearance.

The reference stack is Electron with React, TypeScript, Vite and electron-store, plus a spawned Python process using OpenCV, NumPy, dlib and PyInstaller. It captures at 320 by 240 and 10 frames per second. The source implements per frame face detection, 68 point landmarks and a blink heuristic using mean eye aspect ratio, a rolling 15 sample baseline, an adaptive 15 to 20 percent drop plus an absolute drop threshold, a 0.1 to 0.6 second blink duration and a 0.3 second cooldown. This is implemented detection logic, not evidence of detection accuracy. The included camera check only tests whether a camera opens and returns a frame, the build check verifies files and packages, and the UI test asserts starter template text rather than camera or exercise behavior. The README’s dry eye and strain outcomes are not substantiated by these checks.

The exercise feature is implemented separately from camera tracking. It defaults to an enabled 20 minute interval, lets the user choose 5 to 60 minutes, rotates four fixed prompts, plays a sound, and shows a centered topmost panel that closes after 30 seconds. Skip resets the interval and Snooze schedules another prompt in five minutes. There is no event for completing an exercise and no proof that the prompts produce a health outcome. The actual owners are [Electron main process scheduling and popup code](https://github.com/katunli/ScreenBlink/blob/8b801ce1d43a285938f5fb07ca8bed7a20231080/electron/main.ts#L1566), [exercise copy and actions](https://github.com/katunli/ScreenBlink/blob/8b801ce1d43a285938f5fb07ca8bed7a20231080/public/popup-renderer.js#L33) and [React preferences](https://github.com/katunli/ScreenBlink/blob/8b801ce1d43a285938f5fb07ca8bed7a20231080/src/app.tsx#L650).

ScreenBlink keeps capture in process memory in the inspected path and I found no app level network or telemetry calls there. Python emits face rectangles, twelve normalized eye points, eye aspect ratio, baseline and blink details over stdout; the Electron main process routes those details by IPC to the camera window. A base64 video frame is emitted only after a video stream request. The shared [preload bridge](https://github.com/katunli/ScreenBlink/blob/8b801ce1d43a285938f5fb07ca8bed7a20231080/electron/preload.ts#L66) also exposes camera event subscriptions and a video request function to popup pages, including the exercise page, although the exercise page does not use them. BlinkMore’s existing [WKWebView](https://github.com/Solips1sm/BlinkMore/blob/91f832b4ad0aaf8e7e802c561a4881356a6b6674/BlinkMore/UI/DashboardWindowController.swift#L8) is nonpersistent and restricts navigation and commands to its bundled main page; its current dashboard snapshot intentionally includes live geometry for the Geometry tab. Keep exercise state to prompt text, due state and skip or snooze actions. Do not pass camera frames, landmarks or blink measurements into the exercise UI, persist exercise timestamps, or add exercise events to daily statistics.

The smallest fit is one optional camera independent exercise timer owned by [ApplicationController](https://github.com/Solips1sm/BlinkMore/blob/91f832b4ad0aaf8e7e802c561a4881356a6b6674/BlinkMore/App/ApplicationController.swift), enable and interval preferences in [AppPreferences](https://github.com/Solips1sm/BlinkMore/blob/91f832b4ad0aaf8e7e802c561a4881356a6b6674/BlinkMore/Services/AppPreferences.swift), and a prompt card with skip and snooze actions in the existing local dashboard. Keep blink cues in the existing [ReminderPolicy](https://github.com/Solips1sm/BlinkMore/blob/91f832b4ad0aaf8e7e802c561a4881356a6b6674/BlinkMore/Core/ReminderPolicy.swift). BlinkMore already supplies AppKit, AVFoundation, Vision, its dependency free Rust core and the local WK interface, so there is no integration need for Electron, Python, dlib, or new runtime packages. Add small reminder and dashboard checks for interval, disable, skip and snooze behavior in the existing test structure.

This was read only inspection. I did not run the app, install dependencies or execute tests.
