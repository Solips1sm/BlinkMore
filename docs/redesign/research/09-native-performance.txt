`ApplicationController` is the reliability boundary. Its two second power timer checks AC and reconciles `EyeTrackingService`. Its 50 ms common mode timer evaluates `ReminderPolicy` and drives `OverlayFade`. Camera frame callbacks independently update `MenuBarController`, whose eye icon and 120 ms blink indication are native. `DashboardWindowController` accepts bridge messages only from the bundled main page and refreshes a local, nonpersistent `WKWebView` only while visible, at most five times per second, with one JavaScript update in flight. Closing the dashboard stops loading and releases its refresh timer. WebKit therefore cannot own exercise timing, cancellation, camera control, or reminder delivery.

Add an opt in exercise preference, defaulting off, through `AppPreferences`, its snapshot, the validated `ApplicationController.setPreference` path, and the existing settings controls. Keep the cadence fixed at 20 minutes and check once per minute, with one native pending prompt. Start its 30 second dismissal window only when a visible dashboard presents it. Offer a five minute snooze and never queue missed prompts. A small pure Swift exercise policy should be owned and advanced by `ApplicationController` using `EyeTrackingService.clock()`. Advance active exercise phases against monotonic deadlines. Keep this clock separate from `TrackingFrame.openSeconds`, which counts only fresh camera observations and feeds the existing six second cue policy. Do not change the tracking phase or reminder mode to represent an exercise. A cue that is already fading should take display priority, with the exercise held pending until the cue clears. The screen fade remains owned by `OverlayFade` and exercise visuals never claim that the camera confirmed gaze, distance, or a complete anatomical blink.

Render the current exercise step in a small inline SVG panel in the activity view. Let the native snapshot carry only exercise identifier, status, step, and remaining seconds. The page should send a fixed command such as start, snooze, cancel, or dismiss with an optional built in exercise identifier. Validate those values in Swift and keep SVG paths bundled in the page rather than accepting markup from the bridge. Change SVG classes only when the step changes, respect the existing reduced motion signal, and announce step changes instead of a countdown on every refresh. When the dashboard is hidden or busy, native timing continues and retains at most one pending prompt. Surface that state through a native menu action that opens the dashboard. Do not auto open WebKit from a timer. If a prompt must appear while the dashboard is closed, choose a native notification or panel as a separate presentation decision.

The current `reconcile()` requests camera permission at launch, so a real camera free mode must gate that authorization branch with an explicit camera setting before it runs. Preserve existing behavior for current installs by defaulting camera monitoring to on. Turning it off must stop the service, clear any fade through the existing `stopCamera()` path, and prevent reconciliation from restarting capture while exercise timing remains available. Add a distinct camera off status instead of reusing the five minute pause label. `pauseUntil` keeps its current meaning. The AC agent separately observes power changes, rechecks every two seconds and after wake, terminates the app on battery, and may force termination after two seconds. Exercise sessions should be in memory only, discarded on battery termination, sleep or lock, dashboard close, explicit cancel, and pause. The app currently has no sleep or session lock observer, so add native observers for both. On wake or unlock, start a new cadence and never replay a hidden phase. Camera errors must not fabricate exercise progress; the exercise remains a self guided visual flow when monitoring is off, while the existing camera error and reminder recovery remain native.

Store the opt in preference in `UserDefaults`, whose existing bounded getters supply migration defaults. Do not add exercise rows to `DailyStatistics` or its export. The current `DailyRecord` decoder already accepts optional fields for compatible history, but per exercise timestamps and phase logs would break the existing daily aggregate budget and add no value to this flow. Keep camera frames, contours, and Rust output out of exercise state. Do not change the 640 by 480 capture, 15 fps inference ceiling, single newest pending frame, 250 ms stale rejection, or one pending main thread delivery. No exercise work belongs on the capture or Rust queues. The dashboard can reuse its current five hertz snapshot and the SVG should update only on state changes.

Put schedule, snooze, timeout, cancel, pause, cue deferral, and no catch up assertions in a pure Swift exercise policy test, wired into `scripts/test.sh`. Extend `StateTests.swift` for the disabled exercise default and the camera off preference. Extend `DashboardTests.swift` for the exercise bridge commands, bundled SVG states, accessibility, reduced motion, and native menu entry. Keep `VisionPipelineTests.swift` focused on camera ownership and stale frame behavior. A logged in Mac smoke check owns AC disconnect and reconnect, sleep and wake, lock and unlock, permission denied, camera failure, and dashboard hidden or busy behavior. These checks validate lifecycle and responsiveness only. They do not establish exercise efficacy or camera gaze and distance detection.
